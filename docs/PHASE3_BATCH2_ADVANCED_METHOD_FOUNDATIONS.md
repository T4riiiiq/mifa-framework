# Phase 3 — Batch 2: Advanced Method Foundations

This batch expands Mifa's Windows research catalog on top of the Payload Contract v2 introduced in Phase 3 Batch 1.

## Scope

Six methods are added, each with x64 and x86 release presets:

- `win32-payload-inspect` — build-time payload-contract metadata inspection.
- `win32-file-buffer` — bounded runtime file read into a local read/write buffer.
- `win32-base64-buffer` — bounded Base64 decoding into a local data buffer.
- `win32-hex-buffer` — bounded hexadecimal decoding into a local data buffer.
- `win32-pe-runtime-info` — architecture-neutral PE header inspection from a runtime file.
- `win32-pe-section-characteristics` — bounded PE section-table inspection.

The catalog grows from 28 to 34 methods and from 48 to 60 presets.

## Design constraints

The methods in this batch are inspection and data-handling foundations. They do not execute decoded data, create remote threads, write to remote process memory, allocate executable pages, or load the inspected PE as an image.

`win32-payload-inspect` consumes Payload Contract v2 metadata generated by the existing engine. The Base64 and hexadecimal helpers intentionally accept runtime files and decode them only into local non-executable data buffers. This keeps the methods deterministic and suitable as reusable research primitives without introducing an execution path.

## Validation gates

After installation run:

```bash
python3 -m py_compile mifa.py core/*.py
python3 -m unittest discover -s tests -v
python3 mifa.py check
python3 tools/release_validate.py --compile --json dist/phase3-batch2-validation.json
```

Expected catalog totals are 34 methods and 60 presets. The compile matrix should skip payload-required presets when no payload is supplied; this is intentional.

## Runtime smoke set

A curated Windows smoke pass should cover both architectures before the batch is committed:

- `win32-file-buffer`
- `win32-base64-buffer`
- `win32-hex-buffer`
- `win32-pe-runtime-info`
- `win32-pe-section-characteristics`

The payload inspector can be validated separately using a harmless input through the normal Mifa build command.
